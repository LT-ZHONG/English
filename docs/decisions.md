# 第 1 周选型

这页记录第 2 周可以开工的前提。网络延迟没有在这里测过：当前环境接触不到电信、移动、联通和校园网，不能把建议写成实测结论。

## 决策 1：后端先按 Supabase 官方云做，上线前必须复测

项目已经依赖 `@supabase/supabase-js`，第 2 周先用官方云把登录和同步做出来，开发最快。

能不能继续用，取决于国内四张网的实测，而不是这页的建议：

- 每张网各请求 50 次登录接口或健康检查。
- 成功率不低于 99%，且 P95 低于 1.5 秒：保持官方云。
- 否则改成国内云上的 Supabase 自托管。100 人用一台 2 核 4G 就够。

测完把结果补在这页，再冻结选型。

## 决策 2：邮箱 + 密码，注册必须带邀请码

初期就按这个做。邀请码手工发放，用过即作废，数量就是用户上限。找回密码走邮件。

手机验证码和微信登录需要资质，100 人阶段不做。

## 决策 3：跟读用云端识别，密钥放在后端

浏览器自带的 `webkitSpeechRecognition` 依赖 Google，中国大陆基本不可用，第 3 周替换。方向定为云端语音识别，由后端函数转发，前端只上传不超过 15 秒的录音。

讯飞、腾讯云、阿里云里选一家有免费额度、大陆可访问的，第 3 周开工前定厂商。第 1 周不接入。

## 决策 4：先不让备案挡住内测

大陆服务器加自有域名必须 ICP 备案，大约 1 到 3 周。6 周工期里，内测先用香港节点或云厂商的临时域名。备案同时提交，不放在关键路径上。
